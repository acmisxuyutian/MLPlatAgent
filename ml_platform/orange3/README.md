# Orange3 Workflow Construction Operations

This directory encapsulates workflow editing capabilities for the portable Orange3-3.40.0 distribution, allowing an Agent to construct, modify, and inspect Orange visual workflows through a fixed set of operations.

The target is an existing `.ows` file. Every successful add, delete, or update operation is immediately saved to that file, so the workflow generated by the Agent can be opened directly on the Orange canvas.

## 1. Runtime Environment

By default, the portable Orange distribution included in the project is used:

```text
Orange3-3.40.0/
└── Orange/
    ├── python.exe
    └── pythonw.exe
```

It is recommended to run code from the project root using the portable Python interpreter:

```powershell
.\Orange3-3.40.0\Orange\python.exe your_script.py
```

The public interfaces can be imported from the package entry point:

```python
from workflow_graph_edits.orange3 import (
    add_edge,
    add_node,
    configure_workflow,
    delete_edge,
    delete_node,
    get_test_and_score_results,
    get_workflow,
    open_canvas,
    update_node_params,
)
```

## 2. Specifying the Current Workflow for the Agent

Before invoking any workflow operation, the Agent must call `configure_workflow` to specify:

- the components available for the current task;
- the existing `.ows` workflow file to edit.

```python
from workflow_graph_edits.orange3 import configure_workflow

WORKFLOW_PATH = r"D:\workflows\current.ows"

configure_workflow(
    relevant_widgets_names=[
        "File",
        "Select Columns",
        "Random Forest",
        "Test and Score",
        "Predictions",
        "Confusion Matrix",
        "Save Data",
    ],
    workflow_path=WORKFLOW_PATH,
)
```

`workflow_path` is required. If the file does not exist or cannot be loaded by Orange, a `WorkflowActionError` is raised; no alternative workflow is created implicitly.

Call `configure_workflow` again with another `.ows` file to switch the current workflow. Module-level operations share one current workflow within the same process. To operate on multiple workflows concurrently, use separate `Actions` instances.

## 3. Six Operations Available to the Agent

The following operation names and parameter rules are fixed.

### 3.1 Add a Node

```python
node_id = add_node(widget_name, node_name)
```

Purpose: select a component from those permitted for the current task and add it to the current workflow.

Rules:

- `widget_name` must be present in `relevant_widgets_names`;
- `widget_name` must use the actual Orange component name defined in `widgets.json`;
- `node_name` must be a non-empty Chinese-language name;
- component parameters cannot be configured through this operation;
- the node ID is returned as a string upon success.

Example:

```python
file_node = add_node("File", "读取训练数据")
forest_node = add_node("Random Forest", "随机森林模型")
```

### 3.2 Delete a Node

```python
delete_node(node_id)
```

Purpose: delete the specified node. All edges connected to that node are deleted as well.

Example:

```python
delete_node(forest_node)
```

### 3.3 Update Node Parameters

```python
update_node_params(node_id, widget_name, node_params)
```

Purpose: update component parameters for the specified node.

Rules:

- `widget_name` must match the component actually used by the node;
- `node_params` must be a standard JSON object;
- each parameter name must exist in the component definition in `widgets.json`;
- each parameter value must conform to its defined type;
- only fields explicitly submitted by the caller are updated; all other parameters and default values remain unchanged.

Example:

```python
update_node_params(
    forest_node,
    "Random Forest",
    {
        "n_estimators": 100,
        "use_max_depth": True,
        "max_depth": 8,
    },
)
```

### 3.4 Add an Edge

```python
edge_id = add_edge(source_node_id, target_node_id)
```

Purpose: connect two workflow nodes.

The wrapper automatically selects the most semantically appropriate compatible ports based on the Orange input and output signals. An error is raised when no compatible ports exist, when the connection is duplicated, or when a node is connected to itself.

Example:

```python
edge_id = add_edge(file_node, forest_node)
```

### 3.5 Delete an Edge

```python
delete_edge(edge_id)
```

Purpose: delete a connection by its edge ID.

Example:

```python
delete_edge(edge_id)
```

### 3.6 Retrieve the Workflow

```python
workflow = get_workflow()
```

Purpose: return the current workflow as a standard JSON-ready Python dictionary.

```json
{
  "edges": [
    {
      "edge_id": "936445958711154875",
      "source_node_id": "1",
      "target_node_id": "3"
    }
  ],
  "nodes": [
    {
      "node_id": "1",
      "widget_name": "File",
      "node_name": "读取训练数据",
      "node_params": {
        "source": 0,
        "url": ""
      }
    }
  ]
}
```

A newly created empty workflow should return:

```json
{"edges": [], "nodes": []}
```

Node parameters include the default values defined in `widgets.json`. Node IDs, edge IDs, Chinese node names, component names, and parameters are persisted in the `.ows` file and remain stable after reloading.

### Retrieving Test and Score Results

```python
result = get_test_and_score_results(
    node_id="5",
    timeout=60,
)
```

This API runs the current `.ows` workflow, waits for the asynchronous Test and Score evaluation to complete, and returns standard JSON. `node_id` is optional; when omitted, results for all Test and Score nodes in the workflow are returned.

The returned data includes:

- the evaluation method, number of folds, and whether stratified sampling is enabled;
- the number of data rows actually included in the evaluation;
- the target variable name, type, and discrete values;
- each learner's name and metrics;
- learners that failed during execution and their error messages;
- metrics that could not be calculated and the corresponding reasons.

Classification tasks return AUC, CA, F1, Precision, Recall, LogLoss, Specificity, and MCC. Regression tasks return MSE, RMSE, MAE, MAPE, SMAPE, R2, and CVRMSE.

SQL Table usernames and passwords are still read from the Orange system credential store and are not written to the workflow JSON. A `WorkflowActionError` is raised when the database is inaccessible, node inputs are incomplete, or execution exceeds `timeout`.

## 4. Component and Parameter Definitions

[widgets.json](./widgets.json) is generated from the runtime component registry of the portable Orange3-3.40.0 distribution. It currently contains:

- 33 Orange components that can be mapped to UniPlore;
- component registration IDs, Python classes, categories, icons, and descriptions based on the official Orange documentation;
- the corresponding official documentation path under `orange3-master/doc/visual-programming/source/widgets` for each component;
- input and output signals;
- 221 valid parameters representable in standard JSON, including their types, default values, and Chinese descriptions.

The `description_source` fields for components and parameters distinguish the source of each description:

- `official_document`: the parameter or function can be located in the corresponding official Orange component documentation;
- `source_inference`: the official documentation does not describe it individually, so its meaning is inferred from the `Setting`, parameter name, default value, and UI purpose in the Orange3-3.40.0 component source code.

Example:

```json
{
  "widget_name": "Random Forest",
  "description": "Random Forest 组件，属于“机器学习模型构建”类别。Orange 官方说明：Predict using an ensemble of decision trees.",
  "description_source": "official_document",
  "official_document": "orange3-master/doc/visual-programming/source/widgets/model/randomforest.md",
  "params": [
    {
      "name": "n_estimators",
      "type": "int",
      "default": 10,
      "description": "集成模型中使用的基学习器数量；对树模型通常表示树的数量。",
      "description_source": "official_document"
    }
  ]
}
```

Parameters such as `controlAreaVisible`, `savedWidgetGeometry`, and `selection` represent Orange canvas or component UI state and do not necessarily affect algorithm results. Their descriptions explicitly indicate this distinction.

The Agent can use only components and parameters that are permitted for the current task and present in this file. Component names must use the actual Orange names, for example:

```text
File
Select Columns
Random Forest
Test and Score
Predictions
Confusion Matrix
Save Data
k-Means
```

After changing the Orange version or installing component extensions, regenerate the definitions with:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\Orange3-3.40.0\Orange\python.exe `
  .\workflow_graph_edits\orange3\generate_widgets.py
```

## 5. Example: Constructing a Workflow with the Agent

```python
import json

from workflow_graph_edits.orange3 import (
    add_edge,
    add_node,
    configure_workflow,
    get_workflow,
    update_node_params,
)

WORKFLOW_PATH = r"D:\workflows\classification.ows"

configure_workflow(
    relevant_widgets_names=[
        "File",
        "Select Columns",
        "Random Forest",
        "Test and Score",
    ],
    workflow_path=WORKFLOW_PATH,
)

before = get_workflow()
print(json.dumps(before, ensure_ascii=False))

file_node = add_node("File", "读取分类数据")
select_node = add_node("Select Columns", "选择特征与目标变量")
forest_node = add_node("Random Forest", "随机森林模型")
score_node = add_node("Test and Score", "交叉验证模型评估")

update_node_params(
    forest_node,
    "Random Forest",
    {
        "n_estimators": 100,
        "use_max_depth": True,
        "max_depth": 8,
    },
)

add_edge(file_node, select_node)
add_edge(select_node, forest_node)
add_edge(select_node, score_node)
add_edge(forest_node, score_node)

after = get_workflow()
print(json.dumps(after, ensure_ascii=False, indent=2))
```

The recommended sequence for the Agent is:

1. call `configure_workflow` to specify the current workflow and permitted components;
2. call `get_workflow` to retrieve the state before modification;
3. use the returned node and edge IDs to perform add, delete, and update operations;
4. after creating each node, call `update_node_params` when parameter configuration is required;
5. call `add_edge` to connect compatible nodes;
6. call `get_workflow` again to inspect the final result.

## 6. Converting to UniPlore Workflow JSON

### 6.1 Can All Components Be Mapped One-to-One?

No. A complete one-to-one mapping is unavailable, and component names alone cannot determine whether two workflows are equivalent.

The current portable Orange3-3.40.0 distribution contains 104 non-deprecated components, but `orange3/widgets.json` exposes only the 33 components that can be mapped to UniPlore. The UniPlore reference definition contains 51 components. The comparison is as follows:

- 26 components have identical names;
- 7 components have corresponding functions but different names;
- 33 components in total support component-level conversion;
- 18 UniPlore components have no equivalent implementation in the current Orange distribution;
- the remaining 71 Orange components have no corresponding UniPlore component.

The seven differently named component mappings are:

| Orange3 | UniPlore |
| --- | --- |
| `Correlations` | `Correlogram` |
| `Formula` | `Feature Constructor` |
| `Gradient Boosting` | `Gradient Boosting Decision Tree` |
| `k-Means` | `K-Means` |
| `kNN` | `KNN` |
| `Line Plot` | `Line Chart` |
| `Test and Score` | `Test Score` |

The 18 UniPlore components without an equivalent implementation in the current Orange distribution are:

```text
ARIMA Model
AutoML Training
Change Domain
Image
Image Classification
Infer
Interpolate
LightGBM
Object Detection
One Hot Encoder
Segmentation
Select Best N Attributes
Text
Text Classification
Train Log
Translation
VAR Model
XGBoost
```

Component correspondence does not imply complete parameter correspondence. Parameter names, enum values, and default values may differ between the two platforms. For example:

- Orange `Test and Score` corresponds to UniPlore `Test Score`;
- Orange `SVM.kernel_type=2` corresponds to UniPlore `kernel="rbf"`;
- Orange `kNN.metric_index=0` corresponds to UniPlore `metric="euclidean"`;
- Orange `Data Sampler.sampleSizePercentage` corresponds to UniPlore `percentage`;
- Orange `Random Forest.max_features` is an integer, whereas it is defined as a string in UniPlore;
- components such as `File`, `SQL Table`, and `Select Columns` use different parameter models on the two platforms and cannot be converted losslessly.

UniPlore is a read-only reference. The conversion implementation does not modify any code or component definitions under `workflow_graph_edits/uniplore`.

### 6.2 Conversion Function

Use `convert_to_uniplore_workflow` to convert the Orange JSON returned by `get_workflow()` into UniPlore component names and parameters:

```python
import json

from workflow_graph_edits.orange3 import (
    convert_to_uniplore_workflow,
    get_workflow,
)

orange_workflow = get_workflow()
uniplore_workflow = convert_to_uniplore_workflow(orange_workflow)

print(json.dumps(uniplore_workflow, ensure_ascii=False, indent=2))
```

The function:

- preserves node IDs, edge IDs, Chinese node names, and graph topology;
- converts Orange component names to UniPlore component names;
- converts parameter names, enum indices, and parameter values into the UniPlore definitions;
- fills in default parameters defined in the UniPlore `widgets.json`;
- does not modify the supplied Orange workflow object;
- raises `WorkflowConversionError` when an Orange component has no UniPlore counterpart.

By default, each converted node includes a `matched` field:

```json
{
  "node_id": "4",
  "widget_name": "Random Forest",
  "node_name": "随机森林模型",
  "node_params": {
    "n_estimators": 80,
    "use_max_features": true,
    "max_features": "6",
    "use_random_state": true,
    "use_max_depth": true,
    "max_depth": 9,
    "use_min_samples_split": true,
    "min_samples_split": 4
  },
  "matched": true
}
```

The meaning of `matched` is:

- `true`: the node's UniPlore parameters can be converted semantically from the Orange parameters;
- `false`: the components correspond, but at least one UniPlore parameter cannot be derived losslessly from the Orange state, so the converted result uses a UniPlore default value.

Components with parameter mappings that are always lossy currently include:

```text
AdaBoost
Continuize
Discretize
Edit Domain
File
Formula / Feature Constructor
Predictions
SQL Table
Select Columns
```

Some components can be converted losslessly only for specific parameter values. For example, Orange `Gradient Boosting` corresponds to UniPlore `Gradient Boosting Decision Tree` only when `method_index=0`.

To produce exactly the same node field structure as UniPlore `get_workflow()`, disable the matching marker:

```python
uniplore_workflow = convert_to_uniplore_workflow(
    orange_workflow,
    include_matched=False,
)
```

If node IDs and edge IDs in the two workflows originate from different systems, the JSON objects will not be directly equal even when the components, parameters, and topology are identical. In this case, align nodes by their unique `node_name`, and then compare:

1. the converted `widget_name`;
2. the complete `node_params`;
3. edge connections expressed using node names.

The explicit component mapping table can also be imported directly:

```python
from workflow_graph_edits.orange3 import ORANGE_TO_UNIPLORE_WIDGETS
```

## 7. Opening the Orange Canvas

After constructing a workflow, use `open_canvas` to open the specified `.ows` file in the Orange GUI:

```python
from workflow_graph_edits.orange3 import open_canvas

WORKFLOW_PATH = r"D:\workflows\classification.ows"

process_id = open_canvas(WORKFLOW_PATH)
print(f"Orange process PID: {process_id}")
```

`open_canvas`:

- checks whether the file exists;
- checks whether the file extension is `.ows`;
- checks whether the file has the `scheme` root element required by an Orange workflow;
- launches the canvas using the portable `Orange\pythonw.exe -Psm Orange.canvas`;
- forces the child process to use the Windows graphical backend so that it does not inherit `QT_QPA_PLATFORM=offscreen` from the test environment;
- immediately returns the Orange process PID without waiting for the user to close the window.

This function is independent of `configure_workflow`, so it can open either the workflow currently being edited or any other valid `.ows` file.

To use another portable Orange distribution:

```python
process_id = open_canvas(
    workflow_path=r"D:\workflows\classification.ows",
    orange_directory=r"D:\tools\Orange3-3.40.0",
)
```

If project code is updated while using a long-running interpreter such as the PyCharm Console or Jupyter, restart the interpreter or reload the module before calling the function; otherwise, the old function implementation may still be in use.

## Agent-to-UniPlore Parameter Mapping

`widgets.json` exposes only parameters that affect the semantics of data sources, data transformations, algorithms, evaluation, output, or visualization. Canvas geometry, automatic commit switches, temporary selections, dialog state, graphics rendering caches, and script editor layouts are not exposed to the Agent.

Component names and per-parameter conversion rules can be imported directly:

```python
from workflow_graph_edits.orange3 import (
    ORANGE_TO_UNIPLORE_PARAMETER_MAP,
    ORANGE_TO_UNIPLORE_WIDGETS,
)
```

`ORANGE_TO_UNIPLORE_PARAMETER_MAP` uses Orange component names as first-level keys and UniPlore parameter names as second-level keys. Each rule explicitly records whether the conversion uses direct copying, renaming, enum conversion, multi-parameter composition, a fixed value, or a UniPlore default value.

For example, SQL Table combines `selected_backend`, `database`, `schema`, and `table` into the UniPlore `data_description`:

```text
PostgreSQL table mlagent.public.abalone_test
```

Run the parameter simplification and conversion tests:

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\Orange3-3.40.0\Orange\python.exe `
  .\workflow_graph_edits\orange3\test_conversion.py
```

Run the Test and Score PostgreSQL integration test:

```powershell

.\Orange3-3.40.0\Orange\python.exe `
  .\workflow_graph_edits\orange3\test_test_and_score_results.py
```

`WorkflowActionError` is raised when workflow operation rules are violated. `WorkflowConversionError` is raised when conversion encounters unsupported components, unsupported parameters, or an invalid graph structure. The calling Agent should catch these exceptions and correct its input according to the error message.
